### 13:00 — README model name fix

Found the discrepancy during the audit. The README's model progression table lists:
- `DeepSeek-V4-Flash, V4-Pro` for the deepseek tier

But `deepseek.ts` uses:
- `deepseek-chat` (for the `chat()` method)
- `deepseek-reasoner` (for the `reasoner()` method)

These are the actual DeepSeek API model identifiers. The README names are marketing names. If someone reads the README and tries to call the API with model=`DeepSeek-V4-Flash`, they'll get an error.

Fixed: changed the README to list `deepseek-chat, deepseek-reasoner`.

## WHAT I LEARNED TODAY

1. **Run tests before reading code.** The test results tell you where the pain is before the source does. All 4 repos passed their tests — that tells you the code is structurally sound before you even open a file.

2. **Don't fix what isn't broken.** I wrote a vitest config for voxel-logic and then deleted it. The repo uses jest. The tests pass. Adding vitest support without being asked would have been changing infrastructure for no reason.

3. **README discrepancies matter.** The model names in the README didn't match the API identifiers in the code. That's the kind of thing that wastes someone's afternoon when they copy-paste from docs into an API call.

4. **The tile system is deeper than it looks.** It's not a cache. The confidence/decay mechanism means tiles that stop being useful fade. That's personality formation through use and disuse — the same mechanism that shapes human habits.

5. **The fleet runner is honest about simulation.** The `[simulated]` prefix on fallback responses is good engineering. It would be easy to fake the AI responses and no one would know. Instead, the system is transparent about what's real.
